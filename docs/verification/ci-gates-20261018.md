## 2. Layout lock: why it failed on `main`, and the fix

- Run 39111975064 (official image, `598e93f`): 61 failed, 37 passed, 500 not run (`maxFailures: 60`).
  Every failure was a `toHaveScreenshot` comparison; geometry assertions passed.
- Cause: committed baselines dated from 2026-10-14 (`22ef7be`). Later merged, intended changes
  moved pixels: reference homepage (PR #100), footer spacing, 44-50 px touch targets (#102, #109,
  #111). Page heights, old to new: `/` 5658 to 3485 px (Chromium iPhone), phone pages +16 to +24 px,
  laptop-1440 pages -72 px (footer), sheets (menu/search/language) unchanged in size.
- Fix: the documented `update_baselines` dispatch (run 39112479743, artifact `layout-report`
  sha256 `c46c0059...c94f`), then review: 351 PNGs differ, 3 per project are identical, nothing else
  changed. `/` and `/quote` were compared side by side (old | new). PR #121 contains only these
  PNGs plus the test/config changes below.
- Proof: the PR's own `layout lock` job (no `update_baselines`), run 39117144355 on `46de4ca`:
  **606 passed, 16 skipped, 0 failed, 0 flaky** (10.6 min). Skips are the by-design ones (e.g. the
  menu sheet exists on phone/tablet only); not re-audited one by one here.

## 3. Browsers

| Engine | Coverage in CI | Result |
|---|---|---|
| Chromium | 6 device projects + `premium-360` | 372 + 23 passed |
| WebKit (Safari engine) | `webkit-iphone`, `webkit-ipad-portrait`, `webkit-ipad-landscape` incl. screenshots | 188 passed |
| Firefox | **new** `firefox-premium-360` (functional/geometry suite, no screenshots) | 23 passed |

Firefox was not a configured project before. Making it run needed three things, in order:
1. `HOME=/root` for the Playwright step (Firefox refuses to start when `$HOME` is not owned by
   the user; first run: all 23 failed in 1-5 ms with that message).
2. A test tolerance, not an app fix: the "category names are not cut off" check compared
   `scrollHeight` with `clientHeight`; Firefox measured 66/61 px for one ckb label (the last
   visible line's ascent/descent) while nothing was hidden (a hidden line would add >= one font
   size). The check now requires an overflow of at least one font size.
3. A WebKit iPad flake in `unified.spec.ts` ("homepage search"): text typed before hydration is
   lost. It failed 3 times in one run and passed in three others on the same tree. The test now
   waits for the hydrated footer button (same wait `domain.spec.ts` uses). No app change.

Firefox screenshots are deliberately not compared (no Firefox baselines). Firefox has no
`isMobile` emulation, so it runs the 360 px suite as a desktop-engine page.
Local browsers: still not installed here; `playwright install` stays forbidden. All browser
evidence above comes from the hosted official image.
